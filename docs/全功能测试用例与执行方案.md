# 朝堂全功能测试用例与执行方案

> 状态：待执行。依据 `docs/USER-GUIDE.md`、现有 `docs/ACCEPTANCE-TEST-PLAN.md` 和当前源码功能清单制定。本文列的是**应验证的能力**，不表示能力已经通过。原 A01—A12 验收包保留作端到端样本，本方案补齐逐项覆盖。

## 一、测试目标与判定口径

目标是逐一核对朝堂的**入口、实际操作、产物、失败处理、重启保持和权限边界**。每个用例记录 `通过 / 失败 / 阻塞 / 不适用 / 未测`；“阻塞”须写明缺少入口、模型、网络、操作系统能力或外部服务中的哪一种。源码存在服务类、按钮能点击、模型声称完成、构建成功，均不能代替对应功能通过。

每次执行记录：用例 ID、版本/commit、系统与 Electron 版本、模型与配置（不记录密钥）、开始时间、工作目录、步骤、实际结果、日志/截图/产物路径、失败复现方法。敏感信息脱敏。发现手册声称与实际入口不符时，登记为**文档与产品差异**，不得直接划为“通过”。

### 测试环境与样本

| 代号 | 环境或样本 | 用途 |
| --- | --- | --- |
| E1 | Windows 桌面版，干净用户数据目录 | 主验收环境；重启、文件、命令、插件、密钥保护 |
| E2 | 浏览器开发版 | 验证 Web 模式限制、界面与兼容性 |
| E3 | 本机模拟 LLM，提供确定性文本、工具调用、超时与错误响应 | 稳定自动化回归，不消耗真实模型额度 |
| E4 | 至少一个真实模型；跨模型路由另配第二个 | 模型兼容及内容质量抽样 |
| F1 | `node tests/acceptance/prepare.cjs` 生成的独立样本项目 | 代码修改、工具、权限及自主执行；每轮重新生成 |
| F2 | `node tests/acceptance/mock-server.cjs` 本地模拟服务 | 浏览器、消息与 HTTP 集成 |
| F3 | 文本、CSV、DOCX、PDF、XLSX、PPTX、PNG 样本及损坏文件 | 附件与多模态；答案预先确定 |

自动化层级：**U** 纯函数单元测试；**I** 模拟服务/工具集成测试；**D** 桌面或浏览器界面端到端；**L** 需真实模型或外部服务的受控验收。U/I/D 应作为发布门禁；L 记录模型随机性，重复运行并核对实际产物。对外部平台没有可用凭证时，使用本机协议模拟测试内部链路，同时把真实平台联调记为阻塞。

### 逐项执行规则

矩阵共 **80 条主用例**。一行列出多个动作或工具时，须将每个动作/工具另记一条子结果，例如 `G06-03/read_file`、`G06-03/read_directory`、`G06-03/search_code`；任何一项失败，主用例不得标为通过。每条子结果分别执行正常输入、错误输入和权限边界（若适用）。

执行记录可复制如下表格；证据应指向截图、日志、模型请求、实际文件或导出物，不能只写“观察正常”。

| 用例/子项 | 状态 | 实际结果 | 证据路径 | 缺陷编号/阻塞原因 | 执行者与时间 |
| --- | --- | --- | --- | --- | --- |
| Gxx-xx/功能名 | 未测 | | | | |

每组先跑正常链路，再注入错误、超时、拒绝授权，最后重启核对持久化与恢复。修改代码后重跑相关失败项及其上游、下游用例；发布前重跑全部关键路径。若执行中发现手册列出的功能不在矩阵，先补用例，再给出该功能的验收结论。

### 皇上参与标记

矩阵末列标记谁需参与：

- **无需**：臣可用隔离样本、模拟服务或现有环境执行并留证；常规界面点击与测试审批也由测试执行者完成。
- **条件需**：本地模拟部分仍可先测；只有实网联调、真实模型费用、外部账号或在皇上日常设备安装时，才需皇上提供配置或配合操作。凭证请在朝堂设置界面自行填写，测试记录不得抄录密钥。
- **需**：只有皇上能给出产品取舍或最终发布决定；这类决定不代替功能测试。当前矩阵无必须先由皇上参与才能开始的用例。

条件需参与的内容集中在：真实模型及跨模型路由（G02-02、G02-03、G02-04、G02-05、G03-01、G03-06、G04-11、G05-01、G06-12、G08-06），真实网络搜索（G06-01），插件市场账号（G07-05，如需登录），真实企业微信收发（G08-01、G08-02），以及在皇上日常设备上安装/升级（G01-01、G09-07）。已有可用测试配置时，无须再次参与。其他用例由测试执行者独立完成。

## 三、执行顺序与发布门槛

1. **静态和快速回归**：`npm run type-check`、`npm test`、`npm run test:security`、`npm run build`。当前 Vitest 已覆盖部分任务树、调度、恢复、唤醒和存储逻辑；新增用例应补真实工具、设置及跨模块集成，不重复只测函数内部实现。
2. **模拟集成**：使用 E3/F1/F2，把 G03—G08 的确定性链路加入自动测试，断网和失败分支与成功分支同等重要。
3. **界面端到端**：用 Playwright 控制桌面版，覆盖启动、设置、朝议、计划批准、工具审批、报告、历史与重启。每项保存截图、日志和实际产物。
4. **真实模型抽样**：在相同版本和样本上至少重复三次；按预先写好的事实答案、文件改动和测试退出码判定，不以措辞好坏代替功能结果。
5. **发布判定**：G01、G03、G04、G05、G06 的关键路径和 G09 安全边界必须通过；其余在手册中声称可用的功能若未通过，必须修复或标明实验性/不可用。所有失败与阻塞附复现证据，不以“未运行”记通过。
