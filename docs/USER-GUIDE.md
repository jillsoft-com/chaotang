## 1. 产品简介

**朝堂**是一款多角色 AI 议事与决策辅助桌面应用。它将六位 AI 大臣（丞相、户部尚书、太傅、大将军、御史、司礼监总管）聚集在虚拟朝堂之上，从不同立场对同一议题展开辩论，最终由用户"拍板"形成结构化决策报告。

**核心特色：**

- **多角色辩论**：六位大臣各有立场，互相辩驳，提供多维度视角
- **角色独立模型**：每个角色可绑定不同 LLM（如丞相用 GPT-4o，御史用 Claude）
- **古代朝堂文化**：圣旨/拍板/点名/退朝等仪式感交互
- **决策可视化**：拍板后自动生成共识/分歧/风险/假设四象限报告
- **丰富工具链**：文件操作、代码搜索、Git、浏览器、MCP 协议、Lint 检查等 30+ 工具
- **插件扩展**：支持 SKILL.md 自定义插件，内置插件市场
- **本地优先**：所有数据本地存储，API Key 加密保存，MIT 开源

## 2. 安装与启动

### 开发模式

```bash
# 安装依赖
npm install

# 启动 Web 版（浏览器访问 http://localhost:3000）
npm run dev

# 启动 Electron 桌面版
npm run electron:dev

# 构建生产版本
npm run build

# 打包为桌面应用
npm run electron:build
```

通过 `npm run electron:build` 打包后，可在 `release/` 目录下找到安装包：
- Windows：`朝堂 Setup x.x.x.exe`
- macOS：`朝堂-x.x.x.dmg`
- Linux：`朝堂-x.x.x.AppImage`

## 4. 核心功能：朝议

### 4.1 发起朝议

在首页的输入框中输入议题，点击"开朝"按钮即可发起一场朝议。

**操作步骤：**
1. 在顶部输入框输入议题（如："是否应该引入微服务架构？"）
2. 选择参与的大臣（默认全部参与）
3. 可选设置工作目录
4. 点击"开朝"按钮

### 4.2 @ 点名大臣

在输入议题时，输入 `@` 可以弹出大臣选择列表，直接点名特定大臣参与朝议。

**示例：**
```
@丞相 @御史 分析一下这个技术方案的安全风险
```

被 @ 的大臣将优先参与本次朝议，其他大臣不参与。

### 4.3 选择参与角色

左侧边栏有角色复选框，可以控制哪些大臣参与朝议。默认全部选中。取消勾选的大臣不会参与当次朝议。

### 4.4 设置工作目录

点击输入框旁的"文件夹"图标，可以选择一个工作目录。设置后：
- 大臣们可以读取/写入该目录下的文件
- 代码搜索、Git 操作等工具会自动以该目录为根
- 仓库级上下文会自动索引该目录

### 4.5 朝议模式

朝堂支持三种辩论执行模式，在设置中可切换：

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| **串行模式** | 大臣依次发言，每位大臣可看到前位的发言 | 深度讨论、仪式感 |
| **并行模式** | 所有大臣同时发言，互不可见 | 快速获取多角度意见 |
| **Agent 模式** | 丞相先拆解任务，再分配给各大臣执行，最后丞相汇总 | 需要执行具体操作的任务 |

### 4.6 拍板与圣旨

当所有大臣发言完毕后，可以点击 **"拍板"** 按钮结束朝议。拍板时需要输入"圣旨"——即你的最终决策。

圣旨可以是：
- 一段简短的决策描述
- 对各大臣意见的取舍
- 下一步行动指示

拍板后系统会自动：
1. 生成**决策报告**（四象限）
2. 解析圣旨中的**行动项**
3. 将朝议存入历史记录

### 4.7 退朝

点击"退朝"按钮可终止当前朝议（不生成决策报告），返回欢迎页。

## 5. 召见模式（一对一私聊）

在左侧边栏点击某位大臣的"召见"按钮，可进入一对一私聊模式。

**特点：**
- 只有你和指定大臣对话
- 大臣可以持续多轮对话
- 适合深入探讨特定问题
- 可自由切换不同大臣

## 6. 决策报告（四象限）

拍板后，系统自动由丞相 LLM 生成结构化决策报告，包含四个象限：

| 象限 | 说明 |
|------|------|
| ✅ **共识点** | 多位大臣共同支持的观点、事实或结论 |
| ⚔️ **分歧点** | 大臣间存在争议或不同立场的内容 |
| ⚠️ **风险清单** | 需要注意的潜在问题、障碍或代价 |
| 🔍 **待验证假设** | 尚未确认、需要后续验证的前提或数据 |

报告还包含：
- **一句话决策结论**（verdict）
- **下一步行动建议**（nextSteps）

在历史页面中，决策报告以摘要卡片形式展示。

## 7. 圣旨执行闭环

拍板后，系统可以从决策报告或圣旨文本中自动解析行动项并执行：

1. **行动项解析**：自动识别"创建文件"、"执行命令"、"搜索代码"等行动
2. **自动执行**：调用对应工具完成操作
3. **执行报告**：生成带状态图标的 Markdown 格式执行报告

通过 store 的 `executeImperialDecree(debateId)` 方法触发执行。

## 8. 会话管理

### 8.1 多标签页

应用支持多标签页管理：
- 每次发起朝议或召见都会创建新标签
- 点击标签切换会话
- 右键标签可进行：关闭、关闭其他、关闭所有、复制、重命名、分叉等操作

### 8.2 会话分叉（Fork）

右键标签选择"从此分叉"，或点击发言上的分叉按钮，可以从指定发言位置创建新会话分支。新会话保留分叉点之前的所有发言，生成新的会话 ID。

### 8.3 复制会话

右键标签选择"复制会话"，可以创建当前会话的完整副本（含所有发言），方便对照分析。

### 8.4 重命名会话

右键标签选择"重命名"，可以修改会话标题（议题名称）。

## 9. 历史朝议

点击底部导航的"历史"进入历史页面，查看所有已完成的朝议记录。

### 9.1 全文搜索

在搜索框输入关键词，可搜索：
- 议题标题
- 圣旨内容
- 大臣发言内容
- 标签

### 9.2 标签管理

**添加标签：** 在每条朝议卡片上，点击"+ 新标签"输入框，输入标签名后回车。

**删除标签：** 点击朝议卡片上的标签 × 按钮。

**按标签筛选：** 点击标签云中的标签，可筛选显示包含该标签的朝议。支持多标签组合筛选。

**清除筛选：** 点击"清除筛选"按钮。

点击历史卡片可直接重新打开该朝议。

## 10. 设置

### 10.1 LLM 模型配置

在设置 → LLM 管理中可以添加/编辑/删除 LLM 模型配置。

**支持的 Provider：**

| Provider | 说明 |
|----------|------|
| **OpenAI** | GPT-4o、GPT-4、GPT-3.5 等 |
| **Azure OpenAI** | Azure 部署的 OpenAI 模型 |
| **Anthropic** | Claude 系列 |
| **Google** | Gemini 系列 |
| **Ollama** | 本地部署模型 |
| **OpenAI Compatible** | 任何兼容 OpenAI API 的服务（如 DeepSeek、Moonshot 等） |

**配置字段：**
- **名称**：自定义标识名
- **Provider**：模型提供商
- **模型**：模型标识（如 `gpt-4o`、`claude-sonnet-4-20250514`）
- **API Key**：密钥（加密存储）
- **Base URL**：API 地址（自定义端点时填写）
- **Temperature**：创造性程度（0-1）
- **Max Tokens**：最大输出长度

**测试连接：** 添加模型后可点击"测试"按钮验证连通性。

**远程获取模型列表：** 填入 Base URL 后可自动拉取可用模型。

### 10.2 角色模型绑定

在设置 → 角色设置中，可以为每位大臣指定使用的 LLM 模型。

- 默认所有角色使用同一个模型
- 可为每个角色单独选择不同模型
- 例如：丞相用 GPT-4o（全面分析），御史用 Claude（严格审查），户部用 DeepSeek（数据计算）

### 10.3 朝代主题

朝堂内置多个朝代主题，每个主题将六位角色映射为不同朝代的官职：

**内置朝代：** 夏朝、商朝、周朝、秦朝、汉朝、唐朝、宋朝、明朝、清朝

**行业主题：**
- **现代**：CEO / CFO / 首席顾问 / COO / 合规官 / CSO
- **IT 开发**：产品经理 / 项目经理 / UI 设计 / 前端开发 / 后端开发 / 测试

在设置 → 朝代主题中切换，切换后角色名称和头衔会相应变化。

### 10.4 自定义主题

支持创建自定义主题：

1. 点击"新建主题"
2. 输入主题名称和图标
3. 编辑每个角色的名称和头衔
4. 可选编辑每个角色的系统提示词
5. 保存后立即生效

### 10.5 角色提示词

每位大臣的行为由其系统提示词（System Prompt）定义。

**提示词来源：**
- **MD 文件**：默认从 `src/prompts/` 目录读取（如 `chancellor.md`）
- **自定义**：在设置中直接编辑，优先级高于 MD 文件

### 10.6 技能管理

在设置 → 技能管理中，可以查看和管理所有可用技能。

**技能列表**展示每个技能的：
- 名称、图标、描述
- 所属类别（信息获取 / 数据分析 / 系统工具 / 内容生成 / 验证审核）
- 包含的工具列表

**角色绑定：** 可以控制每位大臣启用/禁用哪些技能。

### 10.7 消息集成（企业微信）

在设置 → 消息集成中配置企业微信 Webhook：

1. 填入企业微信群机器人的 Webhook URL
2. 可选填入签名密钥（Secret）
3. 点击"测试连接"验证
4. 可开启"辩论完成后自动推送结果"
5. 可启动 Webhook 回调服务器（接收群内消息触发朝议）

### 10.8 高级设置

| 设置项 | 说明 | 默认值 |
|--------|------|--------|
| **工具调用最大轮次** | 单次发言中工具调用的最大循环次数 | 30 |
| **上下文压缩阈值** | 对话字符数超过此值时自动压缩历史 | 50000 |
| **摘要模型** | 用于上下文压缩的 LLM（可选独立模型） | 默认模型 |
| **暗色模式** | 切换亮色/暗色主题 | 亮色 |

### 11.2 MCP 协议接入

朝堂支持 **Model Context Protocol (MCP)** 协议，可接入外部 MCP Server 扩展工具能力。

**支持的传输方式：**
- **SSE**（Server-Sent Events）：通过 HTTP 长连接通信
- **stdio**：通过标准输入/输出通信

MCP 工具在朝议过程中动态注册，大臣可以直接调用 MCP Server 提供的工具。

### 11.3 浏览器自动化

基于 Playwright 实现，大臣可以：
- 打开网页并获取内容
- 截图查看页面
- 获取页面结构（无障碍树）
- 点击按钮、填写表单
- 执行 JavaScript 提取数据

## 12. 插件系统

### 12.1 SKILL.md 格式

插件通过 `SKILL.md` 文件定义，使用 YAML frontmatter + Markdown 格式：

```markdown
---
id: my-plugin
name: 我的插件
description: 这是一个示例插件
icon: 🔧
category: system
tools:
  - name: my_tool
    description: 工具描述
    parameters:
      type: object
      properties:
        input:
          type: string
          description: 输入参数
      required: [input]
handler: |
  async function my_tool(args) {
    return { result: args.input.toUpperCase() }
  }
bindTo:
  - chancellor
  - general
---
```

**字段说明：**

| 字段 | 必填 | 说明 |
|------|:----:|------|
| `id` | ✅ | 插件唯一标识 |

## 15. 自学习系统（GEPA）

参考 Hermes 的 GEPA（Generative Embedded Policy Architecture）机制，实现跨会话自学习：

**学习来源：**
- 决策报告中的**行动项**（nextSteps）
- 决策报告中的**风险项**（risks）
- 决策报告中的**共识点**（consensus）

**学习流程：**
1. 每次拍板生成决策报告后，自动提取经验模式
2. 重复出现的模式自动增强计数
3. 高频模式（出现 ≥3 次）可升级为 Skill
4. 学习成果通过 `localStorage` 持久化存储

**效果：** 使用越久，系统越了解你的决策偏好和常见问题模式。

## 17. Agent-to-Agent（A2A）协议

朝堂实现了 A2A 协议，可与其他 AI Agent（如 Codex、Hermes、Qoder）互派任务。

**Agent Card：** 描述朝堂的能力（多角色辩论、代码分析、文档解析等技能）。

**任务派发：**
- **出站任务**：向远程 Agent 发送任务请求
- **入站任务**：接收外部 Agent 发来的任务，转化为朝堂朝议

**远程 Agent 发现：** 通过 `/.well-known/agent.json` 端点自动获取远程 Agent 的能力描述。

## 19. 常见问题（FAQ）

**Q: 如何同时使用不同的 AI 模型？**
A: 在设置 → LLM 管理中添加多个模型配置，然后在设置 → 角色设置中为每位大臣指定不同模型。

**Q: 大臣可以读写我电脑上的文件吗？**
A: 可以。设置工作目录后，大臣可以通过工具读取/写入该目录下的文件。文件写入操作会产生 Diff 预览供确认。

**Q: 如何导入外部工具？**
A: 两种方式：1) 通过 MCP 协议接入 MCP Server；2) 创建 SKILL.md 插件文件放入插件目录。

**Q: 辩论结果可以导出吗？**
A: 可以。拍板后的决策报告和历史朝议都可以查看。支持通过企业微信 Webhook 推送到群聊。

**Q: 支持哪些 AI 模型？**
A: 支持所有 OpenAI API 兼容的服务，包括 OpenAI、Azure OpenAI、Anthropic Claude、Google Gemini、Ollama 本地模型、DeepSeek、Moonshot 等。

**Q: 如何自定义角色？**
A: 在设置 → 朝代主题中创建自定义主题，可修改每个角色的名称、头衔和系统提示词。

**Q: 历史朝议会占用多少存储空间？**
A: 所有数据存储在 `localStorage` 中，通常每个浏览器有 5-10MB 的限额。大量朝议后建议定期清理不需要的历史记录。
