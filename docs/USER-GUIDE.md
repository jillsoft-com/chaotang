## 1. 产品简介

**朝堂**是一款多角色 AI 议事与决策辅助桌面应用。它将六位 AI 大臣（丞相、户部尚书、太傅、大将军、御史、司礼监总管）聚集在虚拟朝堂之上，从不同立场对同一议题展开辩论；结论直接沉淀为会话记录、任务树与交付报告，用户可以继续追问直到满意。

**当前主要能力：**

- **多角色辩论**：六位大臣各有立场，互相辩驳，提供多维度视角
- **角色模型配置**：可为每位大臣绑定模型配置；实际调用以兼容 OpenAI Chat Completions 的接口为主
- **古代朝堂文化**：议事/点名/召见等仪式感交互
- **决策报告**：共识、分歧、风险、待验证假设四象限（当前默认停用，见下文）
- **Agent 任务树**：计划确认、递归拆解、依赖调度、执行监护、快照与事件日志
- **编码任务辅助**：可视化计划编辑、仓库检索、自动测试与 Lint 修复循环、验收和交付审阅
- **本地优先**：会话与设置主要存于本机；桌面版 API Key 使用系统安全存储加密。议题与工具结果会发送给所配置的模型服务

### 开发模式

```bash
# 安装依赖
npm ci

# 启动 Web 版（浏览器访问 http://localhost:3000）
npm run dev

# 启动 Electron 桌面版
npm run electron:dev

npm run build
```

`electron-builder` 配置将安装包输出到 `release/`。本轮仅验证生产构建和 Electron 生产模式启动，尚未验证安装、升级及卸载。配置的打包目标为：

## 4. 核心功能：朝议

### 4.1 发起朝议

先在**设置 → LLM 管理**配置并测试模型，再回首页输入议题，按 Enter 或点击发送按钮发起朝议。空模型配置当前不会在发送前拦截，可能产生网络错误；请先完成配置。

**操作步骤：**
1. 在首页底部输入框输入议题（如：“是否应该引入微服务架构？”）
2. 选择参与的大臣（丞相始终参与，其他角色可自由勾选）
3. 可选设置工作目录
4. 按 Enter 或点击输入框右侧发送按钮；Shift + Enter 可换行

### 4.2 @ 点名大臣

在输入议题时，输入 `@` 可以弹出大臣选择列表，直接点名特定大臣参与朝议。

**示例：**
```
@御史 分析一下这个技术方案的安全风险
```

被 @ 的大臣将优先参与本次朝议。丞相始终参与，无需 @ 指定。

### 4.3 选择参与角色

欢迎页的角色卡片上有复选框，可以控制哪些大臣参与朝议。

> **丞相为必选角色**：所有模式下丞相都始终参与（卡片左上角标有"必选"徽章，复选框置灰不可取消）。其他角色可自由勾选或取消。

取消勾选的大臣不会参与当次朝议。

### 4.4 设置工作目录

点击输入框旁的“工作目录”按钮选择目录。设置后，已授权的文件读取、写入与代码搜索工具以该目录为边界；写文件和执行命令仍须按弹窗确认。更换工作目录后，旧目录不再属于当前授权范围。请勿把私密目录作为测试目录。

### 4.5 朝议模式

朝堂支持三种辩论执行模式，在会话工具栏中切换：

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| **串行模式** | 大臣依次发言，每位大臣可看到前位的发言 | 深度讨论、仪式感 |
| **并行模式** | 大臣可并发发言，彼此不依赖前一位发言 | 快速获取多角度意见 |
| **Agent 模式** | 丞相先拆解任务，再分配给各大臣执行，最后丞相汇总 | 需要执行具体操作的任务 |

### 4.6 自主执行模式

在 Agent 模式下，**丞相在拆解任务时会自动决定哪些角色需要自主执行**。需要创建文件并验证结果的角色（如写代码、运行测试）会被标记为自主执行，只需输出方案的角色（如 UI 设计、需求分析）则一次性输出。

**工作原理：**

```
目标 → 调用工具执行 → 审查结果 → 如有问题 → 调整方案 → 再执行 → 直到目标达成
```

每个被标记为自主执行的角色默认最多迭代 **10 轮**，并受节点与整棵树的工具调用预算约束。模型给出完成声明后仍应检查实际文件、命令退出码和测试结果；不能只凭回复文字判定成功。

**拆解计划中的标记：**

在丞相的拆解计划中，被标记为自主执行的角色名称后会出现 🔄 图标：

```
1. 🎨 UI设计（无标记 = 一次性输出设计方案）
2. ⚔️ 前端开发 🔄（自主执行 = 写代码 + 编译验证 + 迭代修复）
3. 🔍 后端开发 🔄（自主执行 = 架构设计 + 构建验证）
4. 🏮 测试 🔄（自主执行 = 运行测试 + 质量检查）
```

**典型场景：**

| 场景 | 自主执行行为 |
|------|-------------|
| IT 开发团队写代码 | 创建文件 → 编译验证 → 报错则改代码 → 重跑 → 直到通过 |
| 企业团队生成方案 | 生成文档 → 数据校验 → 发现不一致 → 修正 → 验证通过 |
| 朝堂制定策略 | 制定计划 → 可行性检查 → 发现风险 → 调整方案 → 重新评估 |

**IT 开发团队的特殊增强：**

在 IT 开发主题下，前端开发、后端开发、测试三个角色的提示词已内置了开发执行规范：

- **前端开发**：创建文件后编译验证，失败则分析报错、改代码、重跑，反复直到构建通过
- **后端开发**：构建验证 + 使用 search_code 确认修改不影响其他文件
- **测试工程师**：实际运行测试命令 + 运行 lint_check/type_check 检查代码规范

**流水线上下文传递：**

Worker 可接收前序任务的裁剪摘要；具体文件与工具结果仍应通过实际工具核查。

> **注意**：自主执行仅在 Agent 模式下生效。丞相会根据任务性质自动判断，无需用户手动干预。危险命令仍需用户手动批准。

### 4.7 任务树调度

在 Agent 模式下，丞相拆解任务后，系统构建**任务树**，由调度器按依赖和优先级推进。只读任务可并行，写任务受串行与资源锁限制。

**核心特性：**

- **层级结构**：根节点代表整体任务，一级节点是丞相分配的子任务，Worker 可按需继续拆解；默认最大深度 3、单节点最多 5 个子节点、全树最多 20 个节点
- **依赖感知**：子任务可声明依赖关系，调度器确保依赖完成后才执行后续任务
- **渐进拆解**：Worker 收到任务后可进一步拆解为更细粒度的子任务（最多 3 层）
- **状态跟踪**：每个节点有 13 种状态（pending → ready → running → completed/failed 等）
- **快照与恢复**：任务树快照写入历史记录；检测到中断快照时，会提示继续或重新开始。恢复是否安全仍须结合写操作的实际结果核对

**调度流程：**

```
丞相拆解 → 构建任务树 → 调度器找就绪节点 → 执行或拆解 → 收集结果 → 递归协调下一个
```

**与自主执行的关系：**

任务树调度器负责决定“执行哪个任务”，自主执行引擎负责“如何执行一个任务”。两者协同工作：

- 调度器从任务树中选取就绪的叶子节点
- 如果节点标记为自主执行，委托给自主执行引擎迭代完成
- 如果是普通节点，使用标准工具调用循环执行
- 执行完毕后更新节点状态，触发下一个就绪节点

> **提示**：执行前会显示计划审阅面板，可增删一级子任务、修改任务描述与执行者，并切换自主执行或只读模式。节点依赖、优先级和树内移动仍没有界面编辑入口。

> **收尾说明**：大臣发言结束后，本轮自动归档为“已完成”并写入历史记录，不再有“拍板／退朝”按钮。要继续讨论直接在输入框发言或 @ 点名即可，会话会随之回到进行状态。

### 4.8 执行监护

在 Agent 模式下，系统内置**执行监护器**（Execution Guardian）自动监控任务执行过程，防止死循环、停滞或资源浪费。

**监护能力：**

| 检测类型 | 触发条件 | 自动动作 |
|----------|----------|----------|
| **循环检测** | 相同工具及参数反复调用，达到配置阈值 | 暂停节点 + 提示用户 |
| **停滞检测** | 多轮没有可识别的进展 | 暂停节点 + 提示用户 |
| **预算守护** | 工具调用数或迭代轮数接近/超出预算 | 警告 / 强制终止 |
| **自动重试** | 只读任务临时失败（网络/超时）且未超重试上限 | 自动重试（最多 2 次，带退避） |

**用户交互：**

当监护器检测到异常时，会弹出提示框提供以下选项：
- **重试**：重置节点状态并重新执行
- **跳过**：标记节点为跳过状态，继续执行后续任务
- 关闭弹窗按当前处理路径返回；请在会话中核对该节点后续状态

**成本归因：**

执行过程中会追踪工具调用预算；任务树汇总时会给出成本归因，包含节点的：
- 迭代轮数、工具调用数、耗时、估算 Token 数

这有助于了解哪些任务消耗了最多的资源。

### 4.9 并行执行与依赖编辑

**只读任务并行：**

调度器默认启用 `readonly-parallel` 模式，当多个就绪节点均为只读任务（如搜索、分析、读取文件）时，会并行执行以提高效率。写操作任务（如创建文件、执行命令）仍然串行执行以避免冲突。

**手动调整依赖：**

调度器底层支持排序、增删依赖、改优先级和移动节点，并校验结构与循环依赖。计划审阅面板目前只支持编辑一级子任务及其执行者、描述和模式；**依赖、优先级与节点移动没有界面入口**。若这些结构不合适，可取消并改写议题后重试。

**文件变化唤醒：**

调度器支持按指定文件创建或修改条件唤醒等待节点；当前界面没有单独配置这一条件的表单，该能力主要供任务树内部使用。

**事件日志导出：**

任务树会记录状态变化等事件。有任务树快照的会话，可在工具栏点击“导出任务树事件日志”保存 Markdown；导出后请核对时间线和实际产物。

### 4.10 编码任务的规划、验证与交付

在首页选好**工作目录**并进入 Agent 模式后，可按以下顺序处理编码任务：

1. **审阅计划**：丞相拆解后，在计划面板中增删一级子任务、修改描述和执行者，选择自主执行或只读，再批准执行。计划概述可查看，节点依赖与优先级目前不能在面板中编辑。
2. **执行与验证**：自主执行的节点可读写文件、运行命令，并在验收修复后进入测试与 Lint 循环。系统会尝试检测项目命令、分析失败并修复；Lint 自动修复若改动代码，会重跑测试并重新验收。是否通过应以实际检查记录为准。
3. **审阅交付**：会话完成且验收满足交付条件时，交付面板展示文件变化、检查结果和待关注事项。可查看差异、确认交付或请求撤销；撤销会核对文件版本，遇到用户后续修改或缺少可靠原始内容时会跳过并提示冲突。

若项目没有可检测的测试或 Lint 命令，不能把“未检查”理解为通过。普通会话与 Agent 模式的交付条件不同；Agent 模式会逐一核对执行节点的验收记录。交付面板的审阅也不替代人工运行应用并检查需求是否真正满足。

Git 工具包含差异摘要、创建分支和按指定文件提交；提交前应核对文件范围与审批内容。当前没有从交付面板直接创建 PR 的完整流程，也没有自动为每个任务启用独立 Worktree。

### 4.11 仓库理解与扩展模块

选择工作目录后，Agent 可构建项目结构、代码块、符号和引用索引，并把相关片段注入任务上下文。`symbol_lookup` 可按名称查找定义或引用；符号提取覆盖 TypeScript、JavaScript、Vue、Python、Go 等文件。索引扫描有文件数量与单文件长度上限，缓存可能短时滞后；定位关键修改时应再次读取源码。当前代码检索采用 TF-IDF 基线，不能将其等同于已接通外部嵌入模型的向量服务。

以下模块已有实现，但使用范围须区分：

| 模块 | 当前实现 | 使用边界 |
| --- | --- | --- |
| 子 Agent 策略 | 内置代码审查、安全审计、测试三种策略；丞相可在拆解时指定，自主执行路径会附加提示词与工具约束 | `.chaotang/subagents/*.md` 的扫描函数尚未接入会话启动流程；没有管理界面，普通 Worker 路径也未应用该策略 |
| 长期目标 | 任务树可保存目标、成功标准与进度；调度器可检测停滞并在目标未达成时请求重规划 | 当前会话流程未见设置长期目标的入口，普通 Agent 任务不会自动启用该机制 |
| 模块依赖图 | 项目索引提取部分 TS/JS 导入关系，提供依赖查询与循环检测函数 | 尚无独立界面；解析范围有限，结果须对照源码 |
| 代码审查状态 | 服务层可记录变更并标记接受、拒绝或批量处理 | 尚未接入交付面板及提交门槛；面板中的差异查看不等于该服务已生效 |
| Git Worktree | 服务层有创建、列出、移除和在工作树中运行命令的方法 | 未接入任务树执行路径；当前任务不会自动获得独立分支和工作树 |

## 6. 决策报告（四象限）

决策报告由丞相 LLM 汇总发言记录生成，包含四个象限（当前默认停用，恢复方式见 `ChatSession.vue` 的 `enableDecisionReport` 与 `debate.ts` 的 `completeDebate`）：

| 象限 | 说明 |
|------|------|
| ✅ **共识点** | 多位大臣共同支持的观点、事实或结论 |
| ⚔️ **分歧点** | 大臣间存在争议或不同立场的内容 |
| ⚠️ **风险清单** | 需要注意的潜在问题、障碍或代价 |
| 🔍 **待验证假设** | 尚未确认、需要后续验证的前提或数据 |

报告还包含：
- **一句话决策结论**（verdict）
- **下一步行动建议**（nextSteps）

在历史页面中，决策报告以摘要卡片形式展示。

## 10. 设置

### 10.1 LLM 模型配置

在设置 → LLM 管理中添加、编辑或删除模型配置。首次使用请先填写有效配置并点击“测试连接”。

**接口兼容范围：**

| Provider | 说明 |
|----------|------|
| **OpenAI 及兼容端点** | 当前聊天请求统一走 OpenAI Chat Completions 形式；可配置 OpenAI、DeepSeek、通义兼容端点、Moonshot、Ollama 等地址 |

**配置字段：**
- **名称**：自定义标识名

## 12. 插件系统

### 12.1 SKILL.md 格式

插件通过 `SKILL.md` 文件定义，使用 YAML frontmatter + Markdown 格式：

```markdown
---
id: my-plugin
name: 我的插件
description: 这是一个示例插件
icon: 🔧
category: system
tools:
  - name: my_tool
    description: 工具描述
    parameters:
      type: object
      properties:
        input:
          type: string
          description: 输入参数
      required: [input]
handler: |
  async function my_tool(args) {
    return { result: args.input.toUpperCase() }
  }
bindTo:
  - chancellor
  - general
---
```

**字段说明：**

| 字段 | 必填 | 说明 |
|------|:----:|------|
| `id` | ✅ | 插件唯一标识 |
| `name` | ✅ | 显示名称 |
| `description` | ✅ | 描述 |
| `icon` | | 图标（emoji） |
| `category` | | 分类：information/analysis/system/generation/verification |
| `tools` | ✅ | 工具定义列表 |
| `handler` | | JavaScript 代码（async function） |
| `bindTo` | | 绑定到哪些角色 |

### 12.2 插件市场

仓库有插件市场服务代码，但当前设置页只有**本地插件管理**，未见远程市场搜索、安装和更新入口。市场功能暂按开发中处理。

### 12.3 手动安装

桌面版在**设置 → 插件管理**可“导入插件”“打开插件目录”“重新加载”。也可把 `SKILL.md` 放入插件目录后重新加载，并在列表中核对加载结果、工具数量与错误信息。插件 handler 会执行代码，安装前应审阅来源与所需权限。浏览器版没有同等本地目录能力。

- 🗣️ 自由辩论

每个模板包含占位符（如 `{project}`），填入具体信息后即可生成完整议题。

## 14. 后台任务与长辩论

项目包含后台任务调度器，并在会话右侧任务面板显示关联任务：

**任务类型：**

| 类型 | 说明 |
|------|------|
| **延时任务** | 指定时间后执行一次 |
| **周期任务** | 按间隔重复执行 |
| **再上奏** | 记录待检查的指标与触发条件，按间隔运行处理器 |
| **长辩论** | 保存阶段列表并按间隔推进阶段计数 |

**当前边界：**未见从界面创建“再上奏/长辩论”的入口；默认处理器主要更新任务状态和提示文本，未重新读取真实指标或自动生成新朝议。任务记录保存在当前存储后端，进程退出时不会继续运行；重新打开应用后才会恢复待执行计时器。

## 15. 自学习系统（GEPA）

GEPA 学习模块会从已生成的决策报告中提取可复用模式：

**学习来源：**
- 决策报告中的**行动项**（nextSteps）
- 决策报告中的**风险项**（risks）
- 决策报告中的**共识点**（consensus）

**学习流程：**
1. 每次生成决策报告后，自动提取经验模式
2. 重复出现的模式自动增强计数
3. 高频模式（出现 ≥3 次）可升级为 Skill
4. 学习成果存于本机存储后端；桌面版可在**设置 → 通用 → 学习成果管理**导出/导入版本化 JSON

模式提取与合并有自动化测试；本轮桌面实测完成空模式 JSON 的导出与导入。含真实模式的长期学习效果仍需验证。

## 16. 多模态能力

**图像：**会话能预览部分图片附件，但当前图像分析模块把图片描述为“base64、若干 bytes”的文字提示，未将像素数据作为视觉消息传给模型。**请勿依赖它识图、OCR 或辨色。**

## 18. 安全与隐私

- **本地数据**：桌面版将会话历史、任务树快照、记忆、学习成果和设置写入 Electron 用户数据目录的 `chaotang-store.json`，并维护 `.bak` 备份；浏览器版使用 IndexedDB，浏览器未提供该接口时退回 `localStorage`。首次启动会复制旧 `localStorage` 数据，旧副本暂不删除；旧模型配置中的明文 API Key 会转入系统加密存储并从旧副本清除
- **存储边界**：桌面版每次写入会更新整个 JSON 文件，历史数据很大时可能短暂阻塞界面；`.bak` 只保存前一个版本，不替代定期导出和独立备份。浏览器版写入是异步的，关闭页面前应等待保存完成
- **API Key**：桌面版经 Electron 安全存储加密保存，不写入模型配置元数据；浏览器版需自行保护浏览器资料。调用远端模型时，请求会发送给所选服务商
- **目录授权**：文件接口只允许访问已选择工作目录及其子目录；通过文件对话框另行授权的导入/导出使用一次性令牌
- **操作审批**：桌面端执行命令前显示完整命令并要求批准；文件写入也有审批。命令本身可能访问工作目录外资源，应只批准可信命令
- **沙箱边界**：有命令安全检查、超时与沙箱配置；不能据此声称系统级网络、CPU 或内存隔离已验证
- **开源 MIT**：全部代码开源，可审计安全性

## 19. 常见问题（FAQ）

**Q: 如何同时使用不同的 AI 模型？**
A: 在设置 → LLM 管理中添加多个模型配置，然后在设置 → 角色配置中为每位大臣指定模型。先逐个测试连接，再验证实际角色请求。

**Q: 大臣可以读写我电脑上的文件吗？**
A: 在桌面版选定工作目录后，具备权限的角色可调用相应工具；文件写入需批准。批准前请核对目标路径与 Diff，命令操作还需核对完整命令。

**Q: 如何导入外部工具？**
A: 当前用户可从设置 → 插件管理导入或重新加载本地 `SKILL.md`。MCP 客户端已有代码，但尚无配置服务器的界面入口。

**Q: 辩论结果可以导出吗？**
A: 会话工具栏可导出 Markdown；有任务树快照时可导出事件日志。企业微信 Webhook 的本机模拟发送已验证，真实群聊推送仍需联调。

**Q: 支持哪些 AI 模型？**
A: 当前聊天实现按 OpenAI Chat Completions 格式发起请求。可使用兼容这一格式的服务；Claude、Gemini 等原生专有接口不能仅凭预设名称认定已适配。

**Q: 如何自定义角色？**
A: 在设置 → 通用 → 朝代主题中创建自定义主题，可修改每个角色的名称、头衔和系统提示词。

**Q: 历史朝议会占用多少存储空间？**
A: 桌面版存于 Electron 用户数据目录下的 `chaotang-store.json`，不受浏览器 `localStorage` 的 5–10 MB 限制，但大文件写入可能变慢；浏览器版主要使用 IndexedDB。重要会话仍建议定期导出备份。
