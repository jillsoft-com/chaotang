# 朝堂功能验收包（2026-10-10）

本手册用于验证产品是否达到预期，而非仅验证界面有没有按钮。每项须记录**实际操作证据**。`通过`表示符合验收标准；`部分通过`表示链路中有一步未完成；`失败`表示可操作但结果不对；`阻塞`表示没有可用入口或缺少外部依赖。不要把模型口头声称“已完成”当作测试通过。

## 一、准备与记录

1. 在项目根目录运行 `node tests/acceptance/prepare.cjs`。它会在系统临时目录新建一个独立样本项目，打印其绝对路径。不要把朝堂源码目录选作测试工作目录。
2. 用桌面版 `npm run electron:dev`，设置一个可用模型，并将打印的样本项目目录选为工作目录。需测试多模型绑定时，再接入第二个模型。记录模型名、日期和朝堂版本；不要记录 API Key。
3. 在样本目录运行 `npm test`，**应有 2 项失败、2 项通过**。这证明待修错误真实存在。以后每次重做代码测试，都重新运行准备脚本，取得新的样本目录。
4. 另开终端运行 `node tests/acceptance/mock-server.cjs`。仅监听本机 `127.0.0.1:9760`，提供浏览器页面和模拟企微接收端。结束测试后按 Ctrl+C。
5. 每项在下表记 `通过／部分通过／失败／阻塞`，并保存截图、导出的报告或终端输出。模型输出有随机性，议事质量测试用相同模型配置重复 3 次；工具、安全与代码结果按实际产物判定。

## 二、核心场景

### A01 基础构建（必过）

在朝堂项目根目录运行 `npm run type-check`、`npm run test:security`、`npm run build`。三条命令均须退出码为 0；随后桌面版能打开设置、首页和新会话。记录报错与运行环境。**构建通过不等于功能通过**。

### A02 多角色议事与决策报告（必过）

把 `decision-case.md` 作为附件，或将其正文粘贴为议题；选择丞相、户部、御史，先以并行模式，再以串行模式各测一次。提示词：

> 根据所附渠道数据，讨论下月 6000 元如何安排试点。请分别计算三个渠道的获客成本、付费转化率与首月扣除投放后的贡献，指出数据不能证明的结论。不要编造留存率。最终保留有分歧的观点。

讨论完成后点击“拍板”生成决策报告。核对答案：搜索广告获客成本 **100 元**、转化率 **2%**、首月贡献 **-750 元**；技术社区 **50 元**、**3%**、**+600 元**；短视频 **200 元**、**0.5%**、**-1500 元**。首月每位新付费客户扣除可变成本为 **75 元**。报告应有共识、分歧、风险、待验证假设，而非仅一段总结。三次运行中至少两次算对关键数字，并明确留存未知，才算内容质量通过。若只绑定一个模型，可测角色差异，但不能声称已验证跨模型路由。

### A03 Agent 自主执行（必过）

把样本项目设为工作目录，切换 IT 开发团队及 Agent 模式，选择丞相、开发和测试角色。输入：

> `npm test` 有失败。请只修复 `src/pricing.cjs` 中的折扣计算，不修改测试文件；运行测试，失败则继续修正。最后说明实际运行了什么命令、测试结果，以及改动的文件。

在计划审核时观察：丞相是否给需要改代码的角色标记 🔄，分析角色是否可保持一次性输出。批准必要的文件写入及命令执行。**通过标准：**实际文件变更仅涉及 `src/pricing.cjs`；重新在样本目录运行 `npm test` 为 **4 项通过、0 项失败**；朝堂会话里有工具调用、失败检查或复验记录。若只出现 `[GOAL_REACHED]`、漂亮总结或“测试已通过”文字，而实际测试仍失败，则判失败。记录每轮调用、批准弹窗与终端结果。

### A04 工作目录与代码检索（必过）

在样本工作目录下要求：

> 用 `search_code` 搜索 `priceAfterDiscount`，给出文件名和行号；再读取该函数，说明折扣公式。

应找到 `src/pricing.cjs` 和 `test/pricing.test.cjs` 中的匹配，且能引用实际行号。若模型凭记忆回答、没有工具记录，不算通过。可另用“拍板／圣旨执行”搜索动作复测，并留意搜索目录是否落在所选工作目录。

### A05 文本附件与图像（分开判定）

- **文本附件：**把 `channel-data.csv` 附上，提问“技术社区的新付费客户数是多少”。应答 **24**，并能说明来源。附件未被读取时判失败。
- **图像：**准备脚本生成 `vision-card.png`。用图片查看器打开，复制**图片本身**后粘贴到会话，问“图片中间四位数字是什么？左右色块各是什么颜色？不要猜测”。不要用普通“添加附件”按钮选 PNG；该入口当前按文本读取文件。真视觉能力应答 **7392、左红右蓝**，且模型请求实际包含图像数据。当前代码可能只向模型传图片存在提示，因此仅答对文字也不足以证明图像链路；应同时检查请求或用新生成的未知样本复验。图片预览成功与识图成功分别记录。

### A06 会话管理与导出（必过）

在 A02 会话完成后，测试重命名、历史检索、会话分叉和 Markdown 导出。用独特词 `CT_CASE_42` 加入议题，跨会话搜索应只命中相应会话；分叉后新旧会话的后续消息应互不影响。导出文件应含原议题、角色发言、决策结论及已显示的统计数据。复启应用后历史仍应存在。

## 三、工具、集成与边界

### A07 浏览器工具

确认模拟服务仍在运行，给有浏览器技能的角色输入：

> 打开 `http://127.0.0.1:9760/page`，读取页面标题，在 `#code` 输入 `CT-42`，点击 `#submit`，再读取 `#result` 的文本。不要只描述操作，要实际调用浏览器工具。

应返回“**验收通过**”，且工具记录依次包括导航、输入、点击、读取。若 Playwright 浏览器未安装，记录为环境阻塞；若按钮可见但工具未调用，记失败。

### A08 本地插件与市场

先在设置的插件管理中尝试导入**生成的样本目录**内 `sample-plugin/SKILL.md`，记录是否成功。当前导入流程可能因插件目录不在已授权工作目录而失败；这本身应记为导入失败。为单独验证加载与调用，再点“打开插件目录”，在其中新建 `acceptance_echo` 文件夹，把样本 `SKILL.md` 复制进去，然后点“重新加载”。应显示“验收回声”和 1 个工具。丞相角色请求调用 `acceptance_echo`，参数 `input=hello`，工具结果应包含 `CT_PLUGIN_OK` 与 `hello`。仅显示插件卡片属于部分通过。再寻找“从远程市场搜索并安装”的用户入口；若没有入口，记“市场功能阻塞”，勿以本地插件成功代替远程市场成功。

### A09 企微消息

在设置里把 Webhook 地址设为 `http://127.0.0.1:9760/wecom`，点击“测试连接”。打开 `http://127.0.0.1:9760/received`，确认收到测试消息。**此项只证明发送和响应解析。**

再启动设置中的本地回调服务器，运行 `node tests/acceptance/send-callback.cjs`。HTTP 200 只证明回调被接收；要判“双向消息触发朝议”通过，须看到新朝议由消息 `CT_INBOUND_42` 自动启动并有回复。若没有，则记部分通过，并注明“入站收到，但未触发朝议”。本地服务器监听环回地址，不能直接当作公网企微回调地址使用。

### A10 后台任务

先寻找从界面创建“再上奏／长辩论”的入口；若无入口，记阻塞。若能创建，使用 1 分钟测试间隔，观察任务在应用保持运行和重启后是否触发，并核对**真实指标是否被重新读取、新奏报是否实际生成**。只显示“已检查”或任务状态变更，属于部分通过。

### A11 MCP 与 A2A

分别寻找可配置 MCP Server、远程 Agent 的用户入口，记录截图。没有入口时记阻塞，不把源码中的服务类当作可用功能。若日后补上入口，再分别验证连接、工具发现、实际调用、断线报错与重连；MCP 的 stdio 和 SSE 必须分别记结果。A2A 须验证远端能读取有效 Agent Card，并至少完成一次双向任务收发。

### A12 工作目录权限与命令保护（必过）

在样本目录发出“读取 `../outside.txt`”和“在工作目录外创建文件”的要求。**只有工具实际拒绝越界**才算通过，模型自行拒绝不能替代权限测试。再触发一次无害命令（如 `npm test`），确认执行前能看到完整命令并由用户决定是否批准；拒绝后命令不得运行。不要用真实私密文件或破坏性命令试探沙箱。网络隔离、CPU／内存隔离若无独立系统级验证，标为“未证实”。

## 四、发布判定

- **演示版可公开：**A01、A02、A03、A04、A06、A12 通过；A05 的图像能力按实测结果措辞；其余未达标功能从宣传页移至“实验性／规划中”。
- **作为编程代理宣传：**A03 在重新生成的样本项目上连续 **3 次**完成，实际测试均全绿，且没有未经批准的写入。
- **作为集成平台宣传：**A08—A11 均有用户入口、真实调用证据和错误恢复记录。

最后附上测试日期、提交号、操作系统、模型配置、失败截图及复现步骤。模型服务与安装包均需各自在目标环境复测。
