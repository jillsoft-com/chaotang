# 朝堂 vs Codex CLI / Hermes Agent / DeepSeek Harness 功能对比

> 更新时间：2026-10-09（P0 全部完成，P1 仅剩 MCP）

> 本文是功能规划与历史对比，部分第三方能力、领先结论及完成状态未经重新验证；当前使用与发布要求以根目录 [README](../README.md) 为准。

## 定位差异

| 项目 | 定位 | 核心场景 |
|------|------|----------|
| **朝堂 (ChaoTang)** | 多角色辩论式 AI 决策辅助 | 多角度分析、角色扮演辩论、项目探索 |
| **OpenAI Codex CLI** | 终端编程 Agent | 代码编写、重构、测试、PR 管理 |
| **Hermes Agent** | 自学习通用 Agent | 跨平台消息、浏览器自动化、自我进化 |
| **DeepSeek Harness** | 插件化 Agent 框架 | "一切皆插件"的 Coding Agent 底座 |

朝堂的独特价值在于**多角色辩论机制**——这是其他三者都没有的。但作为一个 Agent 平台，在工具链和工程化能力上差距明显。

## 朝堂的独特优势（已有，其他三者没有）

1. **多角色辩论机制** — 6 位 AI 大臣从不同角度分析问题，互相辩论
2. **角色独立模型** — 每个角色可绑定不同的 LLM（如丞相用 GPT-4o，户部用 DeepSeek）
3. **古代朝堂主题** — 独特的文化 UI 和交互体验
4. **串行/并行/Agent 三模式** — 灵活选择辩论节奏
5. **文档解析** — 内置 doc/docx/pdf/xls/xlsx 解析（其他三者需插件）
6. **@指定角色** — 精准控制哪些角色参与讨论
7. **工作目录** — 项目级上下文，带入朝议会话
8. **AGENTS.md** — 自动读取项目指令文件，注入系统提示词
9. **代码搜索** — grep/regex 跨文件搜索，智能忽略 node_modules/.git 等
10. **Git 操作** — 专用工具封装常用 git 命令
11. **测试循环** — 自动检测测试框架并执行，支持反复调用直到通过
12. **上下文压缩** — 工具结果截断+LLM摘要双层策略，阈值可配置（10K~200K字符）
13. **Diff 预览** — write_file 自动捕获变更，展示行级 diff，+N/-N 统计
14. **持久记忆** — save_memory/search_memory 工具，自动注入相关记忆到提示词，支持 5 种记忆类型
15. **Session 管理** — 右键 tab 重命名/复制/分叉，发言级精准分叉新会话

## 总结

**朝堂在"多角色辩论"这个维度上是独一无二的**，这是 Codex/Hermes/DS Harness 都没有的差异化能力。

但在 **Agent 工程化**（Plan Mode、Sandbox、MCP、Diff 预览、审批机制）和**编码闭环**（测试循环、Lint 修复、Git PR）方面，与三者有明显差距。

建议优先补齐 **P0 的 5 项能力**，这些工作量不大但能显著提升 Agent 的可靠性和用户体验。中期通过 MCP 和持久记忆补齐生态短板，长期通过 CLI 和插件系统扩大用户群。
